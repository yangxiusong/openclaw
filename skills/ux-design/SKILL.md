## 设计原则

### 尼尔森十大可用性原则

**1. 系统状态可见性**

```
- 及时告知用户当前状态
- 操作反馈（加载、成功、失败）
- 进度指示（进度条、步骤）
```

**2. 系统与现实匹配**

```
- 使用用户语言
- 符合现实习惯
- 避免专业术语
```

**3. 用户控制和自由**

```
- 提供撤销/重做
- 紧急出口（取消、返回）
- 确认重要操作
```

**4. 一致性和标准化**

```
- 遵循平台规范
- 内部一致（相同功能相同表现）
- 符合用户预期
```

**5. 错误预防**

```
- 约束输入（格式、范围）
- 确认危险操作
- 智能默认值
```

**6. 识别而非回忆**

```
- 选项可见
- 历史记录
- 减少记忆负担
```

**7. 灵活高效**

```
- 快捷操作
- 自定义选项
- 新手引导 + 专家模式
```

**8. 审美和极简设计**

```
- 信息分层
- 突出核心内容
- 避免无关信息
```

**9. 帮助用户识别、诊断和恢复错误**

```
- 清晰的错误提示
- 解决方案建议
- 友好的错误语气
```

**10. 帮助和文档**

```
- 帮助文档
- 新手引导
- 常见问题
```

### 格式塔原则

**接近性原则**

```
彼此靠近的元素被视为相关
应用：相关功能放在一起
```

**相似性原则**

```
相似的元素被视为相关
应用：相同功能的按钮样式一致
```

**闭合性原则**

```
人们倾向于看到完整的图形
应用：卡片设计、列表分隔
```

**连续性原则**

```
人们倾向于看到连续的线条
应用：流程引导、视觉动线
```

**共同命运原则**

```
一起移动的元素被视为相关
应用：手风琴菜单、展开收起
```

## 工作流

### 工作流 1: 用户研究

**步骤 1: 确定研究目标**

```
明确研究问题：
- 用户是谁？
- 用户需求是什么？
- 用户痛点在哪里？
- 用户使用场景？
```

**步骤 2: 选择研究方法**

```
定性研究：
- 用户访谈（深度了解）
- 焦点小组（集体讨论）
- 实地观察（真实场景）
- 日记研究（长期追踪）

定量研究：
- 问卷调查（大样本）
- 数据分析（行为数据）
- A/B 测试（方案对比）
```

**步骤 3: 用户访谈**

```
访谈准备：
- 招募用户（5-8 人）
- 准备访谈提纲
- 准备录音/记录工具

访谈提纲：
- 背景信息（职业、习惯）
- 使用场景（何时、何地、为何）
- 痛点问题（困难、不满）
- 期望功能（想要什么）
- 竞品使用（用过什么、感受）

访谈技巧：
- 开放式问题（为什么、怎么样）
- 追问细节（能具体说说吗）
- 避免引导（不暗示答案）
- 观察行为（不仅听其言）
```

**步骤 4: 用户画像**

```
画像要素：
- 基本信息（姓名、年龄、职业）
- 背景信息（教育、收入、家庭）
- 行为特征（习惯、偏好）
- 目标需求（想要达成什么）
- 痛点问题（困难、不满）
- 使用场景（何时、何地、为何）

画像模板：
```

姓名：张三
年龄：32 岁
职业：互联网产品经理
城市：北京

背景：

- 本科毕业，工作 8 年
- 已婚，有一个孩子
- 年收入 40-50 万

目标：

- 提升工作效率
- 平衡工作与生活
- 给孩子更好的教育

痛点：

- 时间不够用
- 信息过载
- 决策困难

场景：

- 通勤路上用手机
- 工作时间用电脑
- 晚上陪家人后用平板

```

```

**步骤 5: 用户旅程地图**

```
旅程要素：
- 阶段（认知、考虑、购买、使用、复购）
- 行为（用户在做什么）
- 想法（用户在想什么）
- 情绪（情绪曲线）
- 触点（与产品/服务的接触点）
- 痛点（困难、不满）
- 机会点（改进空间）

旅程地图模板：
```

阶段：认知 → 考虑 → 购买 → 使用 → 复购

行为：

- 搜索信息
- 对比产品
- 下单购买
- 使用产品
- 推荐他人

想法：

- "这个能解决我的问题吗？"
- "哪个更适合我？"
- "价格合适就买了"
- "怎么用？"
- "确实好用，推荐给朋友"

情绪：😐 → 🤔 → 🙂 → 😊 → 😄

痛点：

- 信息太多，难以选择
- 参数复杂，看不懂
- 支付流程繁琐
- 说明书太复杂
- 售后响应慢

机会点：

- 提供对比工具
- 简化产品介绍
- 优化支付流程
- 提供视频教程
- 建立快速响应机制


### 工作流 2: 信息架构设计

**步骤 1: 内容清单**

```
列出所有内容/功能：
- 功能模块
- 页面列表
- 内容类型
```

**步骤 2: 卡片分类**

```
开放式卡片分类：
- 准备卡片（每张写一个功能/内容）
- 邀请用户分类（5-8 人）
- 记录分类结果
- 找出共性模式

封闭式卡片分类：
- 预设分类
- 让用户将卡片放入分类
- 验证分类合理性
```

**步骤 3: 站点地图**

```
层级结构：
首页
├── 产品中心
│   ├── 产品分类 A
│   ├── 产品分类 B
│   └── 产品分类 C
├── 解决方案
│   ├── 行业方案 A
│   └── 行业方案 B
├── 关于我们
│   ├── 公司介绍
│   ├── 团队介绍
│   └── 联系方式
└── 帮助中心
    ├── 常见问题
    ├── 使用教程
    └── 联系客服

设计原则：
- 层级不超过 3 级
- 每级项目 5-9 个
- 分类互斥且完整
```

**步骤 4: 导航设计**

```
导航类型：
- 顶部导航（适合少分类）
- 侧边导航（适合多层级）
- 底部导航（适合移动端）
- 汉堡菜单（适合内容多）

导航设计原则：
- 清晰可见
- 当前位置指示
- 响应快速
- 移动端友好
```

### 工作流 3: 交互流程设计

**步骤 1: 任务分析**

```
明确用户任务：
- 用户想要完成什么？
- 任务的触发条件？
- 任务的完成标准？
```

**步骤 2: 流程图设计**

```
流程图要素：
- 起点（用户进入）
- 决策点（判断、选择）
- 操作步骤（用户行为）
- 系统反馈（页面变化）
- 终点（任务完成）

流程图符号：
○ 起点/终点
□ 操作步骤
◇ 决策点
→ 流程方向

示例：用户登录流程
○ 用户进入登录页
□ 输入账号密码
◇ 验证是否通过？
  → 是：□ 进入首页 → ○ 完成
  → 否：□ 显示错误提示 → □ 重新输入
```

**步骤 3: 线框图设计**

```
线框图要素：
- 页面布局
- 内容区域
- 功能按钮
- 导航元素

设计工具：
- Figma
- Sketch
- Adobe XD
- Axure
- 墨刀

线框图原则：
- 低保真（关注结构，不关注视觉）
- 快速迭代
- 标注说明
```

**步骤 4: 原型设计**

```
原型类型：
- 低保真（线框图 + 简单交互）
- 中保真（接近最终效果）
- 高保真（与最终产品一致）

原型交互：
- 页面跳转
- 按钮点击
- 表单提交
- 弹窗显示
- 数据加载

原型测试：
- 内部评审
- 用户测试
- 问题收集
- 迭代优化
```

### 工作流 4: 可用性测试

**步骤 1: 测试计划**

```
测试目标：
- 验证设计是否可用
- 发现可用性问题
- 收集用户反馈

测试任务：
- 核心任务（必须完成）
- 常见任务（经常使用）
- 边缘任务（偶尔使用）

招募用户：
- 目标用户（符合画像）
- 数量：5-8 人（定性）
- 或 20+ 人（定量）
```

**步骤 2: 测试执行**

```
测试流程：
1. 介绍测试目的（5 分钟）
2. 填写背景问卷（5 分钟）
3. 完成任务（30-45 分钟）
4. 访谈反馈（10-15 分钟）

测试方法：
- 发声思维（让用户边做边说）
- 任务观察（记录行为、表情）
- 时间记录（完成任务用时）
- 错误记录（遇到的问题）

测试环境：
- 安静、不受打扰
- 录音/录像设备
- 测试设备（手机/电脑）
- 测试原型/产品
```

**步骤 3: 问题整理**

```
问题分类：
- 严重问题（无法完成任务）
- 中等问题（完成任务但困难）
- 轻微问题（小困扰）

问题描述：
- 问题现象
- 发生场景
- 影响程度
- 建议方案
```

**步骤 4: 优化迭代**

```
优先级排序：
- 严重问题 → 立即修复
- 中等问题 → 近期优化
- 轻微问题 → 排期改进

验证优化：
- 再次测试
- 数据验证
- 用户反馈
```

## 设计系统

### 设计原则

**一致性**

```
- 视觉一致（颜色、字体、间距）
- 交互一致（相同操作相同反馈）
- 文案一致（术语、语气）
```

**可扩展性**

```
- 组件可复用
- 支持多端适配
- 易于新增组件
```

**可访问性**

```
- 无障碍设计
- 色盲友好
- 键盘操作支持
```

### 组件库

**基础组件**

```
- 按钮（主要、次要、文字）
- 输入框（文本、数字、密码）
- 选择器（下拉、单选、多选）
- 弹窗（对话框、提示框）
- 导航（菜单、标签、面包屑）
```

**反馈组件**

```
- 加载（旋转、进度条）
- 成功（对勾、提示）
- 错误（警告、提示）
- 空状态（无数据、无网络）
```

## 注意事项

1. **以用户为中心** - 始终从用户角度思考
2. **数据驱动** - 用数据验证设计决策
3. **快速迭代** - 小步快跑，持续优化
4. **跨团队协作** - 与产品、开发紧密配合
5. **文档沉淀** - 记录设计决策和原因
6. **可访问性** - 考虑特殊用户需求
7. **多端适配** - 考虑不同设备体验
